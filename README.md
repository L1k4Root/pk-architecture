# pk-architecture

[![ci](https://github.com/L1k4Root/pk-architecture/actions/workflows/ci.yml/badge.svg)](https://github.com/L1k4Root/pk-architecture/actions/workflows/ci.yml)

**Docs-as-code for software architecture.** An [arc42](https://arc42.org) + [C4](https://c4model.com) +
ADR template, and **`archkit`**, a small dependency-free Python CLI that creates Architecture Decision
Records and lints architecture docs in CI, so the documentation stays true.

> **Resumen (ES):** Plantilla de documentación de arquitectura (arc42, diagramas C4 en Mermaid y ADRs)
> más `archkit`, una herramienta en Python sin dependencias que crea ADRs numerados y valida en CI que la
> documentación esté bien formada: secciones obligatorias, formato y estado de cada ADR, índice
> actualizado, links rotos y diagramas Mermaid válidos. Incluye una GitHub Action reutilizable y una
> guía para escribir documentación que no quede obsoleta.

```console
$ archkit lint docs
docs/adr/0004-use-eddsa.md: ADR007 section '## Consequences' is missing or empty
docs/adr/README.md: ADR008 index is out of date; run `archkit adr index`
docs/architecture/05-building-block-view.md:31: DOC001 broken link: ../adr/0009-queue.md
3 problem(s)
```

---

## Why

Architecture documents usually fail in one of two ways: they are never written, or they are written
once and go stale. This repository attacks both:

- **The template is small and opinionated.** It has twelve short arc42 sections, each with guidance on
  what belongs there, plus a `0000-template.md` for ADRs.
- **Docs live next to the code**, as Markdown and Mermaid, and change in the same pull request.
- **CI checks them.** A broken link, an ADR without consequences, a stale index or an invalid diagram
  fails the build.

The reasoning, C4 practices and review checklist are in **[docs/GUIDE.md](docs/GUIDE.md)**.

## Quick start

```bash
# Use it without installing (uv):
uvx --from git+https://github.com/L1k4Root/pk-architecture@v1 archkit init        # creates ./docs
uvx --from git+https://github.com/L1k4Root/pk-architecture@v1 archkit adr new "Use PostgreSQL for idempotency keys"
uvx --from git+https://github.com/L1k4Root/pk-architecture@v1 archkit lint docs
```

In CI:

```yaml
- uses: actions/checkout@v7
- uses: L1k4Root/pk-architecture@v1
  with:
    path: docs
```

## `archkit` commands

| Command | Does |
|---|---|
| `archkit init [target]` | Copies the template into `target/docs` (refuses to overwrite) |
| `archkit adr new "Title" [--dir docs/adr]` | Next number, kebab-case file name, `proposed` status, today's date; refreshes the index |
| `archkit adr index [--dir …] [--check]` | Regenerates `docs/adr/README.md`, or fails if it is stale |
| `archkit lint [docs]` | All rules below; exit status 1 on any finding |

### Lint rules

| Rule | Checks |
|---|---|
| ADR001 | File name is `NNNN-kebab-case.md` |
| ADR002 | Title is `# NNNN. Title` with the file's number |
| ADR003 | Numbers are unique |
| ADR004 | Status is `proposed`, `accepted`, `rejected`, `deprecated` or `superseded by [NNNN](file.md)` |
| ADR005 | A superseding ADR exists |
| ADR006 | Date is `YYYY-MM-DD` |
| ADR007 | `Context`, `Decision` and `Consequences` exist and are not empty |
| ADR008 | The ADR index is up to date |
| DOC001 | Relative links and images point to existing files (inline code and URLs are ignored) |
| DOC002 | ` ```mermaid ` blocks start with a known diagram type (`flowchart`, `sequenceDiagram`, `C4Context`, …) |
| DOC003 | The required arc42 sections exist |

## Development

```bash
uv sync
uv run pytest            # 24 tests, 100% coverage (90% enforced)
uv run ruff check . && uv run ruff format --check .
uv run archkit lint template/docs
```

The implementation uses only the standard library (`argparse`, `pathlib`, `re`, `dataclasses`), in
about 400 lines across `adr.py`, `lint.py` and `cli.py`.
